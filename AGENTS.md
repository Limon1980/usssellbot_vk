# AGENTS.md — Мастер-регламент проекта VK Барахолка

Мастер-инструкция для автономных агентов и разработчиков в проекте **VK Барахолка** (VK Chat Flea Market bot).
Методология разработки: **Spec-Driven Development (SDD)** с разделением на две фазы: **Архитектор** и **Кодер**.

---

## 1. Контекст окружения и инфраструктуры

- **Проект**: Чат-бот Барахолки ВКонтакте (VK Callback API + long polling / webhook).
- **Стек**: Чистый PHP 8.3 (Native / cURL, без тяжелых фреймворков), веб-сервер Apache2, СУБД MySQL.
- **Локальная рабочая станция**: Ноутбук на Windows. Здесь пишутся спецификации, исходный код и проводится локальная верификация синтаксиса.
- **Боевой сервер (Production)**: Удаленный Linux-сервер под управлением Apache2 + PHP 8.3 + MySQL.
- **База данных**: Находится **ИСКЛЮЧИТЕЛЬНО на боевом сервере**. Локальной копии базы данных нет.
  - ⚠️ **СТРОГО ЗАПРЕЩЕНО**: пытаться подключаться или слать запросы к БД с локального ПК.
  - Все изменения схемы БД оформляются в виде SQL-миграций в папке `migrations/` для последующего выполнения на проде.
- **Регламент доставки (Деплой)**:
  1. Код разрабатывается и коммитится на локальном ПК.
  2. Выполняется `git push` в репозиторий.
  3. На боевом сервере выполняется `git pull`.
  4. При наличии миграций БД они запускаются вручную или скриптами на боевом сервере.

---

## 2. Двухфазный регламент разработки (SDD)

Каждая задача и функционал проходят две изолированные фазы:

### Фаза 1. Архитектор (docs/agents/architect.md)
1. **Зона ответственности**: Анализ требований, бизнес-логики, состояний FSM бота, структуры БД и внешних интеграций (VK Callback API).
2. **Результат работы**: Готовое ТЗ в файле `tasks/task_XX_<name>.md`.
3. ⛔ **СТРОГОЕ ПРАВИЛО**: Архитектор **НЕ ИМЕЕТ ПРАВА** изменять рабочий программный код (файлы `.php`).
4. Если задача затрагивает БД, Архитектор обязан спроектировать чистый SQL-скрипт (DDL/DML) для запуска на боевом сервере и указать его в ТЗ.

### Фаза 2. Кодер (docs/agents/coder.md)
1. **Зона ответственности**: Исполнение ТЗ, созданного Архитектором в `tasks/task_XX_<name>.md`.
2. **Контроль качества**: Обязательная проверка синтаксиса измененных файлов через `php -l`.
3. **Безопасность**: Никаких прямых обращений к удаленной БД локально.
4. **Завершение задачи**:
   - Переименование файла задачи в статус завершенной:
     ```bash
     git mv tasks/task_XX_<name>.md tasks/task_XX_<name>_done.md
     ```
   - Фиксация изменений в Git с осмысленным сообщением.
   - Финальный отчет с чек-листом и SQL-инструкциями для боевого сервера.

## 3. Структура проекта

```
usssellbot_vk/
├── AGENTS.md                   # Мастер-регламент агентов (этот файл)
├── .gitignore                  # Правила игнорирования Git
├── config.sample.php           # Шаблон конфигурации (без реальных ключей)
├── schema.sql                  # Актуальная эталонная схема MySQL
├── docs/                       # Документация проекта
│   └── agents/                 # Системные промпты и инструкции ролей
│       ├── architect.md        # Инструкция для режима Архитектора
│       └── coder.md            # Инструкция для режима Кодера
├── tasks/                      # Задачи (ТЗ) по методологии SDD
│   ├── task_XX_name.md         # Задача в работе
│   └── task_XX_name_done.md    # Завершенная задача
├── core/                       # Ядро бота (FSM, Ads, Media, Admin, User)
├── helpers/                    # Вспомогательные классы (VKHelper и др.)
├── webhooks/                   # Точка входа для VK Callback API (vk.php)
├── migrations/                 # Файлы миграций базы данных
├── scripts/                    # Сервисные CLI-скрипты (миграции, проверки)
└── logs/                       # Логи работы бота (игнорируются git)
```

## 4. Быстрые команды для проверки (Windows PowerShell)

- **Проверка синтаксиса отдельного файла**:
  ```powershell
  php -l webhooks/vk.php
  ```
- **Проверка синтаксиса всех PHP файлов ядра**:
  ```powershell
  Get-ChildItem -Recurse -Filter *.php | ForEach-Object { php -l $_.FullName }
  ```
- **Фиксация завершения задачи**:
  ```powershell
  git mv tasks/task_01_feature.md tasks/task_01_feature_done.md
  git add .
  git commit -m "feat: реализован функционал task_01_feature"
  ```
